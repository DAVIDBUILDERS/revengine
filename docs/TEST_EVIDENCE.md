## Hosted suites and explicit missing test coverage

`supabase/tests/001_security.sql`, `002_oauth.sql`, `003_actions.sql`, `004_ingestion.sql`, `004_model_preparation.sql`, `005_readiness.sql`, `006_strategy.sql`, `007_mandates.sql` and `007_privacy.sql` are rollback-scoped synthetic-data suites for the actual hosted PostgreSQL roles. They must run through `pnpm test:db` against the verified nonproduction project. They do not contact a real recipient. Their setup/admin role is not the role whose permissions are asserted: assertions explicitly switch to authenticated, worker, dispatcher or OAuth roles. The model/preparation suite explicitly states that its second-run harness is **not** a concurrent-session test.

Run the authored independent-session harness, then add/run the remaining platform cases: overlapping global dispatch/model transactions, late/replayed hook deliveries, Vercel start acknowledgement loss, deployment version transition, Storage HTTP authorization and expiry, login refresh/MFA cookies, the complete privacy database + Storage retention/erasure trace, global budget concurrency, provider cost reconciliation, app alert delivery, and full restore/cutover rehearsal. These are required engineering/release work even after credentials become available; adding a credential does not itself complete them.

## Audit findings handled during implementation

- A pre-draft unprocessed reply could be missed by a draft-time cutoff. The provider-evidence helper now uses the proposal/conversation baseline; local tests cover old inbound replies, sender spoofing and unknown timestamps.
- A same-version Sheet edit could change approved scope/contact/bounds. Immutable source snapshots and exact critical-field comparisons now block these changes, with parameterized tests.
- The booking workflow needed explicit conversation ownership transfer and distinct appointment/follow-up timing rules. SQL request handoff/spacing checks were updated; hosted behavior remains unverified.
- A proposed handoff finding stayed visible after a booking. Domain findings now retire obsolete conditions while retaining original evidence, with a regression test.
- Metric audit added future-as-of exclusion, latest corrected value kinds, missing currency/quality/amount guards, and safe-integer aggregation. Domain tests passed; corresponding SQL changes remain hosted-unverified.
- Privacy export/erasure moved from a runbook-only gap to an admin-only executable CLI, complete paginated records/object manifests, retention/reconciliation guards and failure-safe quarantine. Twelve offline tests passed; actual operator, Storage and database execution remains unverified.
- Production preparation previously only checked for a model key. It now invokes a bounded model adapter for eight capabilities, validates selected source facts, records budget/usage, and saves the bounded template plus reviewed wording; technical SEO remains deterministic. SQL claims/cadence/cost gates need hosted verification.

No deployed endpoint, live business result, causal ROI or legacy equivalence is established by this report.
